# U7 实测审计与本轮调整

审计日期：2026-11-03。修改仍未提交。依据 `Spatial_Test_3.mp4`、本地空间会话记录与正在运行的后端配置。

## 已确认的问题

1. **后端仍是旧配置。** 审计时实际进程从 15:14 持续运行；`GET /api/guidance/spatial/config` 返回的 U7 两个动作均没有 `visual_guidance` 和 `ready_hint`。
   因而即使打开更新的 EXE，也仍会收到旧线条，没有内六角模型的拧紧动作。不能只更新 EXE 而继续使用旧后端。
2. **旧时钟是手动、单次、约 3 秒。** 日志中的 play 与 animation_finished 间隔约 3 秒；切换目标后需要再次点击。
   这是播放策略造成的等待，并不是必须增加 GPU 才能修复。
3. **VLM 存在目标混淆。** 多次章级建议把桌边堆叠料卷的蓝色装置认作外挂料盘支架；定位也曾框到其他机身区域。
   真实目标是固定在 Z 立柱上的白色／浅灰色支架及小底座，不能把“出现料卷”当作“底座安装正确”。
4. **部分返回不确定是合理的。** 原图较远，已装好的支架会挡住螺丝和接合细节；不能要求图像判断扭矩。
   另有定位目录只有 input.jpg、prompt.txt，没有结果或错误详情，旧代码把多种异常都折叠成了同一句提示。

视频抽帧和逐会话统计保存在项目外 `Manual2AR-Data/runs/integrated/u7-review-20261103/`，不放入产品资源。
录像只在本地查看，未重新上传到 VLM。下面的识别调整已经过受控请求测试，真实识别效果仍需下一轮实拍验证。

## 已做调整

- 前后端增加 `mesh-loop-v2` 能力校验；旧后端会明确提示重启，不再静默显示旧线条。
- 有有效作用点时自动循环示意，约 1.2 秒一轮。标记丢失、设点或查看定位照片时暂停，恢复有效实时画面后自动继续。
- 删除手动播放／暂停／重播、模拟回放和空间页官方来源按钮；移除 U4–U7 横排导航及主教学页“指导单元”入口。
- 教学分步骤、空间动作、多个作用点都使用可滚动下拉菜单；官方图片同样可以下拉选择。
- AI 状态、证据、补拍建议放在右侧反馈区滚动查看；底部只留简短定位状态。
- 显式点击拍照时，已有授权、未失效的作用点会使用本次拍摄位姿投影，作为目标消歧提示。
  除原图外可额外发送同一照片的局部放大图，排除背景其他装置。没有有效作用点时仍只发原图。
- 位置提示不算识别正确或安装通过的证据；候选框与当前设定的作用点完全不相交时返回不确定，不显示错误高亮。
- 定位／章级建议保存完整 Prompt、原图、可选 ROI、模型结构化原始回复、结果或错误，以及开始／完成／失败耗时事件。
  错误记录不保存密钥、认证头或任意网络异常原文。

## 下一轮怎么测

1. 关闭旧前端，确认后端是新版，再用新交付目录的“启动教学系统.cmd”进入 U7。
2. 相机和画幅不变时沿用原标定；定位纸、打印机及作用点相对位置不变且你确认后，沿用旧作用点。
3. 先选“从上向下滑入料盘支架”，启动相机，观察箭头是否自动反复向下移动；不用再找播放按钮。
4. 下拉切换到安装底座，再切换螺丝 1／2，检查模型尖端位置和持续旋转。
5. 遮住标记再露出，确认提示隐藏并自动恢复；不要把自动动画理解为系统自动执行了实际操作。
6. 靠近实际白色底座，分别试“拍照找位置”“拍照参考”。结果在右侧查看；看不清时补拍接合区域。
7. 已装好的支架无需拆下。如果旧作用点选错了，进入“空间锚点配置”重设，勿把错误位置提示当作模型结论。

“拍照找位置”只针对本次照片，不写入三维位置；“拍照参考”仍是可选建议，不强制通过才能继续教程。
