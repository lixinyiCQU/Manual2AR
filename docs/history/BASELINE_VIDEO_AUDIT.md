## 核心问题

1. **完成条件不够可靠。** S1 仅要求“贴合立柱、两颗螺丝孔位对齐”，未充分表达可见螺丝已安装；通过此条件不能证明螺丝安装，更不能证明扭矩。S2 的“插槽内、最低位置”存在可观察性问题。此前两个生成任务还出现“底座下方、垂直悬挂”等解释，说明编译差异是语义差异，不能只比较措辞。
2. **单图核验随视角变化。** 最新会话共6次：S1完成；S2未完成、未完成、不确定、不确定、完成。最后成功不抹掉中间错误。没有独立逐帧人工标签，不能据此计算识别准确率、误报率或成功率。
3. **标记可见性限制动画。** 1313个 frame 事件中，tracking494、marker_missing671、target_setup_required143、marker_too_small1、target_outside_view4。约51.1%的采样帧为 marker_missing；这是日志事件比例，不等于视频精确掉帧时长。移动相机到近景会使米制动画失去定位依据。
4. **本次分割实际为 CPU。** 最新会话有2次识别、2次 GPU ConnectError 回退、388次 parts.tracked。CPU能维持链路，不保证模型语义或掩膜准确；不能将本视频算作 GPU 跟踪实验。
5. **基线文字与图例能力有缺口。** 基线生成候选未复制人工 U7 的图例/指令配方，画面出现长句或旧样式。它不应通过混入人工验收 Prompt 来“修好”，应从候选生成结构化显示数据。

## 本次未再次发现的旧 bug

这三份生成记录保留了当前单图核验的图片角色/SHA和条件身份检查；最新两份实际 AR 会话均有重新定位确认。因此不能把模型误判重新归因于“参考图当现场”或“自动沿用旧作用点”。既有防污染、迟到结果检查和候选隔离继续保持，不参与性能消融。

## 已加入的对应实验模块

条件语义审核/一次修复针对问题1；视觉图文匹配、结构化部件状态及分阶段编译针对规划对现场利用不足；编号区域及工作掩膜检查针对部件身份错误；多帧核验针对结果抖动；结构化图例与祈使句针对信息混乱。详见 [开关与实验说明](../reference/PIPELINE_ABLATIONS.md)。

标记离镜的物理限制没有靠 VLM 猜测深度来绕过；仍需让标记与工作区域同时入镜。论文启发模块不能承诺消除当前模型的识别错误，必须用真实配对试验验证。
