# U7 打印机工作坐标与复合显示

工作坐标独立于部件识别、教学动画和验收结果；当前实现使用固定标记、相机标定及显式双视角设点。

## 实机使用

关闭旧 EXE，运行当前交付目录的 `启动教学系统.cmd`。进入开箱 U7 的空间指导，选择原来标定过的相机和画幅；只有打印机、定位标记及相关安装点相对位置未变时才沿用作用点。

**先定义一次打印机工作坐标：**

1. 打开“空间锚点配置 → 打印机坐标”。原有相机标定继续使用，不必每次重做。
2. 在固定机架上找三个容易重复辨认的点：O 为原点；第二点沿横梁的 +X 方向，从设备正面看向右；第三点沿立柱向上，定义 +Z。X 和 Z 必须从同一个原点出发且接近垂直，距原点 25–400 mm。不要使用会移动的热床或工具头作为坐标参照。
3. 固定第一视角，依次点 O、X、Z；点击换角度，将摄像头横移约 15–25 cm，保持打印机与定位纸固定。
4. 固定第二视角，再选择**同样三个真实点**。点击重建，查看本张照片上的 O、红 X、绿 Y、蓝 Z。Y 由右手规则计算，不再另选一个点。
5. 确认轴向符合实际后，点击确认保存。若选错，取消后重选；不要求手动旋转每个资产的 XYZ 角度。

O 是本系统的教学工作原点，**不等于打印机固件的机械零点**。系统不发 G-code，不控制任何电机。固定标记与机架的相对位置改变后，需要重新定义工作坐标及相关作用点。

**随后使用动作参数：**

- “安装料盘支架底座”默认工具沿 −Y 朝向螺丝，示意轴长 80 mm；从握持端朝作用端看，默认顺时针拧紧。它依赖你采用上述轴向约定；若当前安装面的方向相反，可在动作参数选择 +Y。
- “从上向下滑入料盘支架”默认沿 −Z 移动 60 mm。
- 顶部“动画管理”可选择 X／Y／Z、正负方向、距离、循环周期；螺丝动作还可调整每轮旋转角度和旋转方向。同一动作的两个螺丝共用参数，操作位置仍分别保存。
- 距离、周期和转角是**教学示意参数**，不是制造尺寸、要求的旋转圈数或扭矩。工具朝向取决于工作轴，不随摄像头转动而改变。
- 选择“原有两点方向”并保存可恢复原来的作用轴和路径；该模式不使用工作坐标的轴、距离或周期设置。未定义工作坐标时，原有指导保持可用。

## 高亮、代理模型与动画同时显示

点击“识别部件”，拍清灰色底座和白色料盘支架；支架可以在桌面单独摆放。识别框先显示，GPU 初始化完成后显示分割高亮与二维支架代理模型。同时，已设置作用点的三维工具或移动动画继续播放。

三者有不同依据：高亮来自本帧的分割跟踪；二维代理模型只示意被识别支架的外形；空间动画来自固定参照、相机标定、已确认作用点及工作坐标。识别支架不会自动改写三维锚点。

同屏叠加始终使用**相同图像的 SHA256、帧号和相机位姿**。GPU 较慢时显示匹配的拍摄帧，不把旧掩码画在更新的摄像头画面上；动画在该帧位姿上连续播放。看不见标记或没有有效作用点时，只隐藏无法定位的三维指导，部件高亮可以继续。

停止跟踪不会删除工作坐标或作用点。晚到的旧任务取消请求不能终止新的 GPU 跟踪。手动标记操作导致部件位置失效时，停止旧跟踪并提示重新设点。

## 数据契约与模块边界

- `packages/contracts/src/manual2ar_contracts/machine_frame.py`：`MachineFrame` 与 `MotionParameters`。前者是右手、米制、刚性的 `marker_from_machine` 4×4 变换；后者携带工作轴、符号、毫米距离、周期、转角和旋转方向。
- `modules/guidance/spatial/machine.py`：两视角重建、正交化、显式确认和独立持久化。O 与 +X 定义 X，移除 Z 在 X 上的分量后归一化，再计算 `Y = Z × X`。重投影、基线、轴长及夹角检查失败就拒绝保存，不用 VLM 猜工作坐标。
- `spatial/visuals.py`：将工作轴变换到标记空间，用机器坐标确定模型绕轴方向；保留原有操作终点，按轴和距离计算动画起点。未启用机器坐标时沿用旧的两点路径。
- `visuals/library.py`、Unity `VisualSceneSampler`：资产组合和通用采样；旋转幅度、方向、周期、路径由声明数据提供。桌面 RGB 与未来原生 AR 共用同一采样器。
- Unity `SpatialMachineWorkflow`、`SpatialMotionPanel`：工作坐标向导、动作参数界面。`SpatialPartsView` 独立绘制高亮、语义框及二维代理；它不再清空三维资产和位姿图层。

持久化位置均在配置的运行目录内：

```text
guidance-spatial/profiles/
  cameras/<camera>.json       # 原有相机内参
  rigs/<rig>.json             # 原有分目标作用点
  machines/<rig>.json         # 新增：工作原点和 XYZ
  motions/<rig>.json          # 新增：按动作保存的参数
  orientations/<rig>.json     # 兼容旧版逐目标模型偏移
```

新的工作坐标只在用户明确沿用或确认后启用。模型模式启用机器坐标时，旧的逐目标旋转偏移不叠加，避免重复调姿。

接口均属于空间指导会话：`POST /machine/candidates` 接受两帧各三点，`POST /machine/confirm` 需要 `confirmed=true`，`POST /motion` 保存声明式动作参数。帧结果返回工作坐标、投影轴、动作参数及场景；相机仍使用原有帧接口。工作坐标的三角化和动画不需要 VLM／GPU。

记录包含两个坐标取景及像素点、重建质量、显式确认、工作坐标 ID 和每帧动作参数。模型渲染和分割跟踪仍分别记录，便于区别锚定问题与感知问题。录屏和自动测试产物保存在项目外 `Manual2AR-Data/runs/asset-library/machine-frame-20261104/`。

## 本轮验收范围

Python 回归覆盖了坐标重建、右手刚体检查、近平行方向／弱视角拒绝、保存确认与重用、原操作终点不变、同一动作的多螺丝共用参数、参数边界，以及晚到的取消请求不影响新任务。

Unity 实际运行验证分割高亮、二维代理、三维动画同屏，旋转幅度确实改变、动作参数界面和错帧拒绝。测试使用受控图像及受控推理结果，不代表现场识别准确率。本轮未新增私有录屏外发或真实 GPU 推理；现场贴合与轴向仍需按上面的步骤复测。

保留的 AR 接口仍使用明确的参考空间与右手米制变换。后续由 ARKit／其他提供方注册世界参考坐标，不能直接把本地 RGB 的二维框当作三维位姿。

本轮实跑记录：全量 Python 回归 325 项通过；补充取消竞态用例后，指导模块最终专项为 120 项通过。Unity 四场景运行时错误为 0，包括三点向导点击／取消、参数化旋转、同屏三图层和错帧拒绝。新构建的交付清单记录源文件与托管程序集 SHA256；实机参数仍需用户复测后确认。

## U7 的先后顺序（2026-11-04 更新）

U7 现在明确按两步进行：先安装灰色支架底座，并拍照通过 VLM 的可见安装检查；再开放“从上向下滑入料盘支架”。第一步拍清立柱上的灰色底座及上下两颗固定螺丝。VLM 无法判断扭矩，机械紧固仍由用户按官方步骤确认。

图文页面的分步骤菜单、下一步按钮，以及空间指导的动作菜单使用同一条前置规则。第一步通过后显示“继续安装料盘支架”；在空间页通过的结果会同步回本次图文教程。重新检查底座未通过、清除其检查或重新开始教程，会重新锁定第二步。人工标记“已操作”、已有空间锚点、分割成功或模拟回放都不能代替底座 VLM 检查。

顺序状态属于当前教程／独立空间会话，不写入相机、工作坐标或作用点配置，不跨新任务自动继承。底座和整个支架的检查使用各自的 Prompt、官方参考图和结果记录。其他章节保留原有浏览方式；用户仍可离开 U7 查看其他章节。

新增契约 `u7_sequence` 返回底座通过状态、支架通过状态和提示；分步骤返回 `locked`。底座和最终安装仍归属 U7 的观察点，通过 `substep_id` 区分具体检查。`u7_sequence.py` 只负责本任务前置关系，不把全系统改成强制核验流程。



## 坐标重建失败诊断

每次有效双视角重建请求均在运行目录 `guidance-spatial/runs/<session>/machine-<attempt>/` 保留诊断包：

- `view-1.jpg`、`view-2.jpg`：原始取景；对应 `*-clicks.jpg` 显示 O、+X、+Z 点击位置。
- `diagnostic.json`：两帧编号、图像摘要、尺寸、相机标定、标记位姿，以及三个点各自的视线夹角、深度、重建位置、两视角重投影误差和拒绝原因；无法计算的后续指标不伪造。
- 成功时另存 `candidate.json`；失败仅记录 `machine.rejected`，不保存工作坐标、不解锁任何操作。

界面显示失败点名称和八位诊断编号。超过 3 像素的偏差可能源自点击、标定或标记位姿，不能仅凭报错断定用户点错。保持打印机和标记固定，两视角依次点击同样的三个实物点；+Z 点应在竖直方向，不能用桌面前后方向代替。阈值保持不变。

日志只在主动提交坐标重建时保存照片，不逐帧保存视频。诊断照片属于本地测试资料，保留在源码目录外；不上传模型服务。需要复测后根据实际误差判断根因，此更新不声称已解决现场的几何误差。
