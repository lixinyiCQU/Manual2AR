# 方向／遮挡审核与状态调度基线

日期：2026-11-11。用户委托“按照你的经验进行方向机遮挡策略的审核，然后进行：‘状态与调度验证’”。本轮按该委托选择方法，审核身份记录为 `assistant_under_user_delegation`。这是方案审核和受控逻辑验证，不声称人工逐张标注、实物确认或视觉算法验证已完成。

## 已采用的方法

### 方向：明确人工确认

底座方向、支架与插槽方向各作为独立人工条件。操作者须对照官方参考图核实；只有本节点要求的视觉条件和依赖通过，才能提交正向确认。方向错误则指出该条件需要纠正。

原因：目前没有经过独立正反样例验证的自动辨向特征，矩形长边或图像上下关系不充分。本基线保留方向要求，明确采用人工渠道；它不是视觉失败时临时降级，也不计入自动视觉能力。之后若引入可靠的自动方法，须创建新的方法／任务版本并独立评价。

### 遮挡：有效历史证据与新证据分开

1. **同会话、同现场上下文：**此前已完整核验的节点，可在后续仅报告正常遮挡时保留其正向证据。底座完整核验包括联合螺丝检查、其他可见条件、方向人工确认及紧固人工确认。
2. **未完整核验的节点：**不能因为曾经看到部分外观就沿用其遮挡后的未知结果。
3. **新会话或新上下文：**不继承旧完成状态。初始支架已装而底座不可见时，保持“支架可见连接”与“底座未知”两个事实，要求补充视角；不自动拆卸，不推断底座已通过。
4. **明确反证或失效：**重新限制相关及依赖节点；清除当前节点需重新确认的人工证据，以及后续节点的旧结果。修复后仍需重新获取被失效的后续证据。
5. **身份不明、画外或细节不足：**不按正常遮挡保留证据。设备、部件实例或布置改变时，用 `context_change` 清空证据并递增 epoch。

是否仍为同一物理对象／上下文，由未来相机适配器或明确用户操作维护；本阶段没有实现自动变化检测。不会仅凭时间或“同一个 session_id”声称实物未变化。

以上策略没有新增“只核验外观即可完成完整安装任务”的窄化目标，也没有为看不见的螺丝添加临时人工绕过。

## 审核与版本

- `ground_truth/u7/v1/candidate/`、`candidate-v2/` 保留历史输入，不覆盖。
- `ground_truth/u7/v1/state-validation/` 是当前冻结输入，版本 `0.2.0-state-validation`，2 节点、8 条件、19 项来源要求。
- 该包包含 5 个视觉条件和 3 个人工条件；M3-8 仍为选材要求，螺丝仍联合核验。
- `review.json` 状态为 `approved_for_state_validation`，范围为 `controlled_facts_only`。真实视觉标准、现场标签及空间 GT 尚未提供。
- `human-review.json` 继续保存两项用户直接选择；方向和遮挡两项记录用户的授权原话、委托审核身份和实际方案结论，不冒充用户逐项选中了某个候选。

## 执行契约

`state.Session` 是独立的内存会话。受控事件必须绑定 session、任务 SHA、epoch、预期 revision 和唯一事件 ID。观察另带递增 frame_id 与输入来源哈希；这里的哈希对应符号标注载荷，不是实机照片证明。

| 事件 | 可产生的状态变化 |
| --- | --- |
| observation | 只更新 vision 条件；明确 true/false，或带原因的 unknown |
| manual | 只更新被指定的人工条件；支持部分确认，不能覆盖视觉条件 |
| claim | 记录输入中实际出现的原话并提示矛盾，不产生完成证据 |
| invalidate | 使指定条件及相关依赖证据失效 |
| context_change | 清空本次证据、递增 epoch，旧请求不能回写 |

事件先整体校验再提交，拒绝时不改变事实、事件日志或 revision。正向人工确认不能跨越视觉失败、视觉未知或尚未满足的前置依赖。

每个条件使用 true / false / unknown。节点状态为 unknown、not_completed、suspected_installed、verified 或 blocked；任务状态由当前条件重新计算，完成标记不是不可撤销的布尔值。

调度按依赖顺序选择目标相关节点，先处理操作前置，再按声明顺序检查可见条件，最后处理人工条件：

- 遇到明确失败，返回 `operate`，指出具体条件，避免重新要求执行整个阶段。
- 遇到视觉未知，返回 `request_view`；前面的关键未知不会被后面的失败条件掩盖。
- 可见条件通过后，缺少人工证据返回 `ask_manual`。
- 目标及必要依赖均满足才返回 `complete`。

操作前置不自动成为永久目标。例如耗材使用后不再“尚未使用”，不能因此撤销正确的装配结果；需要持续成立的要求须在任务中表达为结果／目标条件。本轮针对具有明确装配结果的任务，不实现任意工艺规划和过程历史推断。

节点名、设备名和 U7 条件名都不出现在执行算法分支中。测试还覆盖另一设备、三个重复操作、条件生产者的隐式依赖、外部操作前置和循环拒绝。

## 运行受控验证

仓库根目录：

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -B -m pytest baseline/tests -q

PYTHONPATH=baseline/src .venv/bin/python -B -m manual2ar_baseline validate \
  baseline/ground_truth/u7/v1/state-validation --reference-root .

PYTHONPATH=baseline/src .venv/bin/python -B -m manual2ar_baseline validate-state \
  --bundle baseline/ground_truth/u7/v1/state-validation \
  --cases baseline/validation/u7/state-cases.json \
  --output /tmp/manual2ar-state-validation-new
```

输出目录须不存在。每次保存原验收输入、实际决策、接受事件、预期拒绝、任务／用例／实现指纹和报告。任何预期决策不符都会使命令返回非零。

32 个场景涵盖：底座未装、遮挡未知、疑似安装、完整核验后跳过重装、有无声明的决策一致、声明冲突、联合螺丝缺件、未知优先、人工门控、已装支架、正常遮挡、上下文重置、反证与修复、部分人工确认、方向错误，以及跨会话／任务／版本／帧／epoch 的旧请求拒绝。

本轮测试与符号场景是两种有重叠的验证，不相加为“样本数量”或“视觉准确率”。当前所有视觉输入和人工确认均由测试明确设定；没有真实模型调用、相机、GPU 或 AR 结果。

后续阶段已单独实现 [真实照片观察接口](VISION.md)。以上是第二阶段受控验证记录；照片会话使用独立的 `experimental_photo_analysis` 证据模式，不能混入本节的受控事件。原冻结批准范围不变，真实照片的标签和误差另行审核。
