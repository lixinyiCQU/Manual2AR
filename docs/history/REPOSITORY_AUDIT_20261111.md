# 2026-11-11 ponytail 仓库审查与优化

What this repo does: Manual2AR 是单用户设备教学原型，Unity Windows客户端调用WSL业务后端和可选GPU服务。本工作树扩展了官方Wiki到U7任务、现场对齐、资产绑定和核验的管线。

负载假设：一个操作者、一个后端进程、串行生成任务和少量同时存在的相机会话。不是生产多租户或公网服务。按正确性、状态完整性、测试和简化顺序审查；遵照本次用户授权，在只读审查后执行以下修复。

## Must fix（已修复）

1. **重启会重新信任被修改的候选。**
   - 原行为：`guidance/pipeline.py::Candidate` 在构造时从当前磁盘重新计算指纹；内存检查能挡住会话内修改，但重启后这些修改被当作新基准，可能恢复原approved状态。
   - 修复：生成结束持久封存 `candidate-manifest.json`，涵盖procedure、来源、绑定、观察规范／规则和初始计划；恢复时按原清单检查集合、路径和哈希。恢复批准还核对approval与job记录的procedure SHA。
   - 失败处理：变动／缺失／损坏清单的候选标failed，不注册空间执行路由；不让一份损坏清单导致整个服务启动失败。
   - 验证：批准后分别修改procedure及binding再创建后端，均拒绝恢复；损坏清单测试；原有正常恢复和规范篡改测试保留。封存前的历史候选无法获得追溯保证，重新批准时才能建立当前封存。

2. **启动器会复用过期后端。**
   - 原行为：`deploy/windows/Start-Backend.ps1` 只看automatic_configuration=true，旧进程即使缺少新管线和修复也被当成兼容。
   - 修复：`/health` 返回启动时固定的backend_revision和source_worktree；交付描述符记录同一源码修订。启动器必须同时匹配工作树和修订，才复用服务。
   - 后果：源码更新后会明确拒绝旧服务并提示重启，不自动杀掉他人的工作树。旧描述符需重新交付，不能手填哈希绕过。
   - 验证：描述符与源码修订校验测试、应用健康接口回归，及本轮Windows启动检查记录。

## 复核后不改的旧待办

旧交接曾怀疑原生/world渲染器在同presentation部件减少时留下旧对象。当前VisualAssetLibrary.Validate强制实例数与固定layer集合一致，sampler隐藏实例通过alpha=0表达且不减少采样条目。因此未能在当前合法契约下证明“采样数量减少”的前提；撤回试加的清理循环和错误测试，不为未来假设扩大实现。现有世界坐标／非法参考空间验证继续保留。

## 保留的边界

- 严格观察规范仍需人工审核；已知U7朝向、插入到位缺少可靠特征标准。已有真实调用只是诊断烟雾测试，不能统计为通用迁移或规划成功率。
- 业务API没有公网访问控制。本审查按受控单用户实验使用；公网／多用户部署须另设认证、会话归属和状态隔离，不因GPU有Bearer认证而推定业务API已受保护。
- 验证器使用固定18010端口，须排他运行。并行Agent必须隔离工作树、配置、运行路径和Unity Library。
- 持久指纹防止误改被重启采纳，不是签名系统；拥有文件系统写权限者若同时改清单与文件，不在该保证内。
- 没有对所有文件逐行审查，也没有进行渗透、GPU负载、真实相机／三维精度、多用户或全部Windows DPI测试。
