# U7 前端复评与调整（2026-11-16）

后端已经能给出目标候选、条件级补拍提示和条件剩余计划，旧界面主要读取简短摘要，没有完整呈现这些变化。本轮只调整现有 Unity U7 页面与必要的只读预览接口，保留 GT、AR 资产和其他任务入口。

## 用户能看到的变化

- “下一步怎么做”等范围不明确的提问先展示官方任务候选。选择后仍需点击评估，选择本身不创建执行会话、不调用模型、不记录完成。未支持的目标继续明确提示范围，不提供无关任务兜底。
- 现场证据不足时，按具体检查部位显示补拍原因与建议：遮挡换角度、未入镜拍入画面、细节不清靠近拍、身份不明拍清特征与安装位置。部分视觉条件已满足时同步显示，不将未知说成未安装。
- 当前动作先显示，后面保留官方两步状态概览，标注当前步骤及必要前置。未核实步骤是否需要操作，要等证据补齐后决定；没有把计划中的未来条件分支当成固定操作清单。
- 界面阶段改为“目标与现场、现场结果、操作指导、结果核验”，不再用三步编号与官方两步混在一起。不适用的重播按钮隐藏，官方步骤按钮使用完整宽度。
- 真实模式已接受的照片需要补拍后再评估或核验；未接受的网络失败照片可重试。人工确认和首次查看本步指导不被补拍限制误挡。启动相机仍只取景。
- 换照片后只说明需更新核验结果，不再无条件承诺保留旧前置结论。新的明确反证仍能使旧状态失效。

## 契约与安全边界

增加 `POST /api/guidance/u7-demo/goal-preview`，复用当前 GT 的目标预览和来源候选，接受现有 Start 请求结构。执行会话接口兼容。

Unity 读取 `remaining_plan.current_action.observation_hints`。计划的任务、会话、epoch、revision、当前模式与当前节点必须与 execution 一致；计划只负责说明，execution 继续决定能否播放、人工确认和完成。只有照片回复被成功接受后才标记该照片已提交，避免格式或版本错误误挡重试。

默认历史照片及预设观察和实时模型演示都排除研究评价。本轮没有修改上一轮缓存实验结果、冻结数据或人工标签。
