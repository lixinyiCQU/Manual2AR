# 开箱 U4—U7 Windows 摄像头空间指导演示

2026-11-03：现已增加 U4 运输固定解除和 U5 热床螺丝指导，顶部按章节再选动作。
旧 U6／U7、相机标定与位置设置方式保持兼容。
新增内容及试用顺序见 [开箱扩展说明](UNBOXING_SPATIAL_EXTENSION.md)。

## 打开演示

源码工作树：`Manual2AR-Li/Manual2AR-Integrated`。继续使用 V1 的
`configs/app.local.json`；本功能不需要新的 API Key，也不依赖 GPU 服务。
只有主动点击「拍照参考」才会调用原来配置的 VLM。

1. 在 WSL 的源码目录运行 `bash run.sh start`。旧服务如果已经启动，需要重启才能加载新接口。
2. 打开项目外 `Manual2AR-Data/builds/integrated/Manual2AR-Windows` 中的
   `启动空间演示.cmd`。脚本自动将前端同步到 Windows 本地的
   `%LOCALAPPDATA%\Manual2AR\Desktop` 再运行；后端及数据仍在 WSL。
   本机已复现直接从 WSL/UNC 路径运行时「能枚举相机但无法取帧」，同一 EXE 在本地磁盘
   能正常取帧，因此后续请使用启动脚本。直接双击共享目录中的 EXE 也会尝试转交本地启动。
   全部三个模块可用同目录的 `启动教学系统.cmd` 打开。更新前先关闭旧前端窗口。
   也可在 Unity Hub 添加
   `Manual2AR-Data/builds/integrated/Manual2AR`，使用 Unity 2022.3.34f1，选择菜单
   **Manual2AR → 打开 U6 U7 空间指导演示**，按 Play。
3. 首次先点击「模拟回放」。不需要摄像头、标定纸、API 或 GPU，即可查看随视角变化的
   三维方向线、螺丝作用点和工具轴参照。页面明确标记这是合成回放，不能代表实机检测。
4. 正常教学入口仍是欢迎页 → 操作指导 → 单机开箱 → 步骤总览 → U6 或 U7 →「进入空间指导」。
   返回后保留原教程位置和进度。也可以直接在空间页面切换五个动作。

前后端接口说明：后端启动后打开 `http://127.0.0.1:8010/docs`，查看
`desktop-spatial-guidance` 分组。地址跟随 V1 文件配置中的 `backend.public_url`。

### 已经完成标定和 U7 选点的用户

不需要重新拍棋盘，也不需要重建已有 U7 主位置。关闭旧前端，使用更新后的启动脚本。
启动摄像头后，仅在纸张与打印机确实未相对移动时选择沿用位置。进入 U7 滑入动作，看到
“料盘支架插槽”标签后，点击「播放示意」；可以暂停、继续和重播。
遮挡标记会暂停并隐藏提示，恢复后由你继续播放。

「我已操作」是你自己的记录，不代表 AI 验收通过；「拍照参考」仍只检查本章最后的可见状态。
日常操作栏不再显示棋盘采集等按钮，需要调整时点击「位置设置」，完成后点「返回指导」。
新增的底座螺丝 1／2 各有独立位置；没设置过的螺丝需分别完成一次双视图选点。
视频审计和本轮范围见 `docs/MODULE_TWO_SPATIAL_PROGRESS.md`。

## 实机准备：只做一次的相机标定

1. 点击「打印标定纸」，或打开交付目录中的 `空间定位与相机标定.pdf`。
   两页分别是定位标记和棋盘。打印选择 **实际大小 / 100%**，关闭「适应页面」。
   用尺确认 100 mm 检查线；标记黑色正方形必须为 **80 mm**，棋盘格边长为 **20 mm**。
   纸张贴在平整硬板上。不要使用尺寸不确定的屏幕显示代替实机标定纸。
2. 点击「启动摄像头」。画幅固定为正向 4:3，最大边 960 像素。
   「切换镜头」会轮换 Windows 可用相机。标定绑定设备、原始分辨率、方向和提交画幅。
3. 暂时拿棋盘入镜，不需要同时看到打印机或定位标记。每次点击「采集棋盘」采集一张。
   采集 **至少 12 张**：覆盖中心、四角、远近距离和不同倾角；每张均完整看到棋盘。
   同一位置连续点击会被拒绝。界面显示样本数和需要补拍的原因。
4. 点击「计算标定」。后端执行真实棋盘检测与 OpenCV 相机标定，检查覆盖范围、焦距、
   单视图误差及整体误差，合格后保存。未标定或画幅不符时不会画精确指导。
   如果镜头变焦、自动构图、设备设置发生变化，请重新采集标定；固定相机焦段和数字缩放。

标定文件保存在 V1 配置 `paths.runtime/guidance-spatial/profiles/cameras/` 下。
不用在终端粘贴任何密钥或矩阵。下次同一画幅、同一设备可直接复用。

## 实机准备：固定参照并设置操作位置

本版没有假定厂家提供打印机 CAD，也没有把 VLM 矩形框当成三维位置。
需要开发者／演示准备人员为每个动作设置一次起终点。

1. 将定位标记刚性固定在打印机附近的稳定部位，尽量靠近当前操作区域；相机能同时看到
   标记及作用点。标记不能挡住插槽、螺丝、散热口或运动路径。**打印机保持停机状态**。
   不要在设置后移动打印机、标记、X 轴或其他与目标有相对运动的部件。
2. 选择动作，对照右侧完整的 V1 官方图文。点击「设置起终点」，系统固定当前取景。
   按右侧选点说明依次点击两个位置，黄色十字标记选择结果。
3. 点击「换角度再取景」，保持打印机及标记不动，将相机横移约 15–25 cm。
   两次都必须看到定位标记，不要只原地转动镜头。
4. 点击「固定第二视角」，再次依次选择**同一对真实位置**，然后点击「重建作用点」。
   不能在两个视角里选不同的螺丝或不同的插槽边缘；两个位置应能被重复、准确地指认。
   对工具轴，可使用保持静止的真实工具的手柄轴线点及螺丝中心；不要凭空猜一个屏幕位置。
5. 系统检查视差、两条视线的交会误差、深度、工作范围及线段长度。
   通过后人工确认并点击「确认保存位置」。错误时不会保存猜测结果。
6. 镜头移动时，位置随定位标记姿态重新投影；标记丢失、过小、姿态误差过大或目标出界时，
   空间提示会隐藏。只显示结果对应的拍摄帧，不将旧姿态叠在较新的实时画面上。

每个动作独立保存位置。下次打开必须确认「标记未移动」才可沿用；重贴标记或移动相关
部件后，应为受影响动作重新设置。相机标定解决相机内参，设置起终点解决打印机与标记
的空间关系，两者不能互相代替。

「拍照参考」复用 V1 的 U6-C1／U7-C1 专用 Prompt、图片身份和精简结果契约。
只发送用户点击时的一张当前照片；不上传参考图、不在定位循环里调用 AI。
检查该章节的最后可见安装状态，显示最近一次照片的建议，不阻止切换步骤，不自动宣布
机械安装或螺丝力矩已合格。空间提示不会验证螺丝松紧、真实动态碰撞或工具施力。
当前工具提示是程序生成的三维轴线／圆环，没有复用缺少明确许可的第三方工具模型。

这是 **带参照标记的 RGB 视频 AR**：使用真实内参、真实尺寸、双视图重建及相机姿态；
不依赖 LiDAR。目标是桌面初版可演示链路；尚未测得实机误差、遮挡鲁棒性或操作成功率。
采用最多一个取景请求在途、约 10 Hz 上限的匹配帧显示，实际刷新率取决于 CPU、网络和
Unity 渲染；不是承诺 30 FPS 的本地 SLAM，也不具备无标记世界锚定或自动目标三维初始化。

## 代码边界与数据

- `resources/tasks/bambu_a1_mini/unboxing/spatial/v1/actions.json`：五个动作与官方来源，
  不修改原 `procedure.json`、ObservationNode 或 Prompt 的哈希绑定。
- `packages/perception/src/manual2ar_perception/spatial.py`：标记检测、PnP、像素射线、
  双视图重建、三维指导几何及投影；不依赖教程、VLM、存储或网络。
- `apps/backend/src/manual2ar/modules/guidance/spatial/`：独立会话、标定、人工设置及确认、
  章节拍照参考、打印纸与标记回放。只经模块二组合接口接入，不共享模块一／三的跟踪会话。
- `apps/unity/Manual2AR/Assets/Manual2AR/Scripts/Guidance/Spatial/`：相机输入、匹配帧视图、
  投影几何绘制和启动适配器。与原教程只连接一个入口及一个返回回调。
- 变换为 `T_camera_from_marker`，米，列向量，序列化为 row-major 16 数值。
  相机坐标右／下／前；标记坐标右／印刷顶部／纸面向外。
  像素坐标原点左上，必须匹配相同 `session_id + action_id + client_frame_id + source_sha256`。
- 运行记录位于 `paths.runtime/guidance-spatial/runs/<session>/events.jsonl`。
  每帧记录身份、定位状态和 CPU 处理时间；只在用户明确设置作用点或拍照参考时保存照片。
  设置证据含两张图、原始点击、米制坐标、重投影误差和官方快照身份；确认前不写入可复用配置。
- 会话数量、内存帧缓存、标定样本数受限；关闭视图释放相机、HTTP 请求及后端会话。
  单独保留两张设置用的取景帧，避免换角度期间被实时缓存淘汰。

## 验证与再打包

`bash run.sh test` 执行 Python 回归。空间测试包含真实 OpenCV 标记检测、已知三维位置恢复、
镜头畸变下的双视图重建、弱视差拒绝、相机标定求解、完整棋盘识别、目标保存确认、
旧帧与错误画幅拒绝、标记丢失／恢复，以及无 AI 调用的定位循环。

`tests/unity/ProductValidation.cs` 在 Windows Unity 中运行合成服务，验证三模块原流程和
新增空间入口、随视角改变的箭头／工具轴绘制、点击到像素的映射、U6/U7 切换、返回释放，
并确认教程进度没有被修改。截图与运行结果放在项目外。

源码准备及普通 Unity 项目打包：`bash run.sh package`。
Windows 编译和验证工具：`tools/build/validate_desktop.py`；需要传入 Windows Unity.exe
和位于源码树外的验证工程路径，`--build` 同时生成 Windows Player。
`tools/build/spatial_delivery.py` 将标定纸、启动脚本、说明和清单补入交付目录。
常规回归不调用真实 VLM、GPU 或摄像头。另提供 `tests/unity/SpatialCameraValidation.cs`
及仅编译到隔离诊断 Player 的 `SpatialCameraPlayerProbe.cs`，显式执行本机摄像头取帧检查。
此次 FHD Camera 已在 Windows 本地 EXE 中连续取帧成功，取帧只在内存进行，不保存或上传
现场图像。相机采集通过及合成几何检查均不能替代打印机旁的空间精度和操作效果验收。
