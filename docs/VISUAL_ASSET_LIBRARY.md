# Manual2AR 教学视觉资产库：U7 初版

本轮在 `lixin/asset-library` 开发，仅替换 U7 的空间视觉内容，未提交 Git。官方章节、图文、学习进度与已保存相机标定不改写。U7 增加独立的双部件感知、可见安装检查和模型姿态配置。

## 直接测试

1. 关闭旧 Windows EXE。启动本次交付目录 `启动后端.cmd`，或在 **Manual2AR-Dev** 运行 `bash run.sh start`。同一 8010 端口只能运行一个后端。
2. 运行本次交付的 `启动教学系统.cmd`，进入操作指导 → 打印机开箱 → 外挂料盘／单机 → U7 安装料盘支架 → 进入空间指导。
3. 启动摄像头。定位纸和部件相对位置未变且用户明确确认后，可以沿用已复制的作用点；否则进入“空间锚点配置”重新设点。
4. 底座动作下拉选择螺丝 1／2：应看到金属杆、深色手柄的内六角工具、固定螺丝、琥珀色旋转方向与青色接触环，自动循环。
5. 拍照检查底座通过后，切换“从上向下滑入料盘支架”：应看到简化支架虚影沿已设导向边移动、方向箭头和终点环，自动循环。
6. 遮住定位标记，提示应隐藏；露出标记后恢复。切换目标不应残留上一步模型。官方图片仍可点击放大，AI 建议仍只在点击拍照时请求。

旧版前端／旧版后端与新资产包混用会提示版本不一致。三维资产自动播放本身不请求 VLM／GPU；只有点击“拍照找位置”才启动双部件识别和 GPU 分割跟踪，点击“拍照参考”只请求一次最终可见安装状态判断。

## 统一建模契约

机器可读规范：`resources/visuals/v1/style.json`；共享验证模型：`packages/contracts/src/manual2ar_contracts/visual_assets.py`。

- 米制、右手坐标。工具工作端／插入参照点为原点，+Y 为作用方向；不采用从包围盒自动猜测工作端的方式。
- 外形简洁、轻微倒角、低面数、无纹理。金属杆浅灰、握持部分深青、工具动作琥珀色、移动／定位青色、部件虚影浅灰白。
- 每个资产最多 2400 三角面，每个场景最多 8 层。当前 6 个资产分别为 152、317、400、256、20、124 面，不需要独立 GPU。
- 模型为 `teaching_proxy`：示意外形和动作，不表示制造尺寸、隐藏卡扣、安装间隙、指定扭矩或要求旋转的圈数。
- 模型本体、动作 Clip、场景层、现场作用点分开定义。五类指导均保留目录类别：高亮、移动、手势、工具、情境；本阶段制作高亮／移动／工具，未制作手势骨骼、情境计时器。
- `nominal_axis_m` 是示意轴长。运行时根据已确认的两点设置示意尺度并限制最大尺寸，不把该尺度作为测量结果。
- 两个三维点只约束作用轴和路径；绕轴方向采用定位纸参照。支架虚影的横向朝向是示意，不宣称恢复真实安装面的法向。

## 当前六个资产与两个场景

| 资产 ID | 作用 |
| --- | --- |
| `tool.hex_driver` | 内六角工具，工作端固定，绕工具轴旋转 |
| `motion.turn_arrow` | 与拧紧动作一致的旋转方向 |
| `highlight.target_ring` | 接触点／路径终点 |
| `part.spool_holder_proxy` | 简化支架虚影，随已设置路径移动 |
| `motion.slide_arrow` | 固定的滑入方向 |
| `part.screw_proxy` | 螺丝头、内六角凹槽及短杆示意 |

`u7.holder_base` 组合工具、旋转方向、接触环和螺丝。`u7.holder_slide` 组合移动支架、方向箭头和终点环。周期 1.2 秒；滑入到终点后淡出再循环，不把循环次数计入教学完成状态。

U7 的官方依据仍为开箱 Wiki 中“安装料盘支架”的两项原文，引用 `026a3a3c147bd8b28d5bf414`、`97eeffdb901ac2699a6a9aeb`。模型由本项目程序化制作，未复制第三方工具／支架几何。

## 全链路与代码边界

```text
官方 U7 分步骤、引用
  → actions.json 选择 presentation_id
  → 后端 VisualAssetLibrary 校验目录、版本、拓扑、预算、SHA256
  → 已确认双视图作用点 + 本帧相机位姿
  → VisualPresentation：各层模型／动作／米制变换／路径／参考空间
  → Unity 校验本地资产包与后端一致
  → VisualSceneSampler：同一时钟采样旋转／路径／透明度
  ├─ SpatialAssetGraphic：投影到同一 RGB 快照，保留相机畸变
  └─ VisualWorldRenderer：需要显式注册的 Unity 世界参考变换
```

- `resources/visuals/v1/`：样式、配方、网格、目录；`resources/catalog.json` 注册逻辑资源。
- `tools/assets/blender_library.py`：Blender 内的参数化建模、源文件／FBX／预览输出。
- `tools/assets/build_library.py`：编排生成与校验，将小型运行网格写回 resources；大型源文件留在项目外。
- 后端 `visuals/library.py`：资源校验及组合场景，独立于 VLM 和教程完成判定。
- 后端 `visuals.py`：把资产功能坐标变换到已设置的标记坐标；不改变原几何求解。
- Unity `Scripts/VisualGuidance/`：目录解析、通用动作采样、渲染接口、世界空间适配器，不依赖 U7 控制器或 AR SDK。
- Unity `Scripts/Guidance/Spatial/`：相机快照与资产呈现的适配；旧章节继续使用旧模型入口。
- `bash run.sh sync`：校验后复制目录和网格到被忽略的 Unity Resources；运行时不依赖 Blender，不下载模型。

每帧返回仍包含 `client_frame_id + source_sha256`；资产引用还携带 catalog SHA256、模型 SHA256、版本、Clip ID 与 `reference_space_id`。先验证图像／目标身份，再显示。模型损坏或版本不一致不伪装成新的资产显示。

`GuidanceVisual.presentation` 是兼容性新增字段，旧 `asset` 与线条仍可供旧客户端读取。本轮新客户端在 U7 优先使用组合资产。设置作用点时冻结的选点照片、切换目标、标记丢失继续隐藏资产。部件识别的冻结照片及匹配跟踪帧允许高亮、二维代理和已定位动画叠加。

## 后续原生 AR 接入

`IVisualGuidanceRenderer` 接口和 `VisualSceneSampler` 可以复用。世界渲染器接收明确配准的 `UnityWorldFromReference`，将右手参考坐标以 `(x,y,-z)` 转入 Unity，并修正三角形绕序。其输入参考空间必须与场景相同。

当前没有实现 ARKit 会话、世界配准、场景深度或真实遮挡。后续由 ARKit／其他追踪适配器提供同帧位姿和已注册参考空间，不从生成模型推断它们。现有世界渲染器支持刚性网格和程序动作；手势骨骼、复杂材质及空间文字组件需要独立扩展。

## 重新制作与新增资产

所有模型参数和颜色在 `resources/visuals/v1/recipes/u7.json`；API 参数继续只改配置文件。

由开发工具调用 Blender，用户不必手动输入命令：

```bash
.venv/bin/python -B -m tools.assets.build_library \
  --blender '/mnt/c/Program Files/Blender Foundation/Blender 5.2/blender.exe' \
  --output /home/lixin/projects/Manual2AR-Data/assets/u7-v1.1 --preview
bash run.sh sync
```

产物：独立 `.blend`、FBX、PNG、`index.html` 预览和构建哈希清单。FBX／Blend 的示范关键帧便于本地编辑；运行时以目录 Clip 为准，路径由现场数据提供。新增同类资产可增加配方基本形体、元数据和场景层，渲染器不增加资产 ID 分支。

手工修改 Blender 模型时：保留以资产 ID 命名的根对象，其坐标是功能原点；所有模型置于根对象下，显式应用合理的尺寸和方向。可通过 `tools/assets/export_blend.py` 导出任意已命名根下的静态网格，再用 `tools.assets.import_mesh --mesh <文件> --version <新版本>` 校验并更新已登记资产。导入全库验证通过后才写回；新 ID 先在目录登记锚点／Clip／场景。不要重新运行旧配方覆盖手工编辑；应把源文件和配方版本一起保存。

当前手工导出器支持静态网格及已应用修改器，不支持骨骼动画；不自动猜测功能点。新增动作类型时应扩展共享采样器及其测试，而非在 U7 UI 中编写特殊动画。

## 验收边界

自动检查使用合成标记与受控模型，不上传私有图像。它验证资产包、拓扑、功能轴、组合、姿态／路径、实例切换和渲染，不替代相机实测，也不能证明真实支架方向或安装已正确。实际测试无需拆卸已装好的支架。

Python、Unity 和真实 GPU 的最新验证记录见 `docs/U7_ASSET_TEST_REVIEW.md`。自动验证不代替你的实机场景复测。

## U7 双部件感知与可见安装检查

“拍照找位置”先提示灰色双螺丝底座和白色料盘支架同时出镜，并展示两个官方局部图。VLM 接收当前照片与两张外观参考，分别返回两部件的框与前景点；支架可以独立放在旁边的桌面。先在拍摄照片上显示 VLM 框，再用模块一相同协议调用 SAM3.1 初始化和 Cutie 连续跟踪。

每次跟踪返回必须同时匹配会话、目标批次、帧号和图像 SHA256；Unity 显示该帧原图与其掩码。跟踪延迟时不会把旧掩码画到较新的摄像头画面上。失去目标隐藏高亮并提示重新识别。停止识别、切换步骤、画幅或相机时释放 GPU 会话。模型与位姿动画不依赖该 GPU 会话。

识别到支架后，在支架掩码范围上显示半透明代理模型；它是 `image_proxy` 二维示意，没有深度、物体法向或世界锚点，不会覆盖人工确认的三维作用点。语义、分割、跟踪事件和初始图像、掩码保存在配置的运行目录 `guidance-spatial/runs/<session>/parts-<job>/`；逐帧只记录身份与耗时，避免无限保存照片。

“拍照参考”只检查最终支架与立柱的可见连接。使用与识别外观图不同的官方已安装图作为参考。不要求看见被正常遮住的螺丝、卡扣，不从照片判断扭矩。完成时弹窗明确提示，学习进度仍由用户决定。结果存入 `installation-<id>/`。

## 打印机工作坐标与相机画幅

最新用法见 `PRINTER_WORK_COORDINATES.md`：通过两视角各选 O、+X、+Z 三点，一次确认打印机工作坐标；U7 使用轴、方向、距离、周期和转角驱动教学动作，减少逐个模型调整 XYZ。旧的逐目标姿态数据保留供两点模式兼容，工作坐标模式不会重复叠加它们。

画幅与模块二共用中心裁剪：1:1、16:9、9:16、3:4、4:3。切换关闭当前感知及定位会话，使用新画幅的标定；默认 4:3 保留原相机签名。工作坐标绑定固定标记，可跨已标定相机使用，但每次沿用都需要确认标记与机架未发生相对移动。

新版启动器同步至 Windows 本地的 `%LOCALAPPDATA%\Manual2AR\Desktop-AssetLibrary`，并核验 `Assembly-CSharp.dll`。请从本次交付的“启动教学系统.cmd”进入，旧的 Desktop 缓存版不会自动变成资产库版。

U7 最新按底座可见安装核验 → 安装料盘支架顺序开放，详见 `PRINTER_WORK_COORDINATES.md` 的先后顺序部分。


U7 组件动作管理、模型朝向与路径分离及双向转向箭头说明见 [U7_ACTION_MANAGEMENT.md](U7_ACTION_MANAGEMENT.md)。当前资产目录版本为 1.2.0，几何网格保持原有六个教学资产。
