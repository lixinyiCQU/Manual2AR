# 来源约束的目标定位与证据驱动规划

本轮优化当前任务图内的目标定位和现场规划，不重做说明书编译，不改变正式GT，也不声称支持整份说明书或任意自然语言。U7演示默认使用新策略，旧策略保留用于对照。

## 方法与论文启发

1. **来源关联的目标候选。** 使用官方操作层级、对象名称及任务定义已有的别名，区分操作主体与立柱等背景部件；只对有限问句框架和词序做规范化。借鉴 [CheckManual](https://arxiv.org/abs/2506.09343) 的手册—对象—操作对齐。别名关联来源，不表示别名字串必然逐字出现在官方原文；自动编译的别名仍需审核。
2. **歧义先澄清。** 唯一匹配才建立目标；不明确时提供父任务和细操作候选，绑定任务SHA及来源。借鉴 [KnowNo](https://proceedings.mlr.press/v229/ren23a.html) 的必要求助思想，没有实现其保形预测或统计保证。候选没有伪造的置信度。
3. **部分正证据优先核实。** 当前操作无明确视觉反证，但已有部分可见条件通过、仍有条件未知时，先补拍核实，避免直接重复建议安装。明确未满足仍给操作指导；前置通过、后继视觉条件全部未知时，保留原先查看指导的能力。借鉴 [SayCan](https://say-can.github.io/) 对目标相关性与当前可执行性的区分，以及 [Inner Monologue](https://proceedings.mlr.press/v205/huang23c.html) 的反馈更新。
4. **条件剩余计划。** 输出当前动作、按观测原因区分的补拍提示、必要剩余操作及条件分支，关联来源、条件、事件和照片SHA。未来操作分支必须再次通过运行时节点与动作守卫；AR绑定只关联资产，不授权执行或完成。

视觉、人工、未知三值、依赖、哈希、版本、保存后提交等门控保持原规则。补拍目标只说明拍清什么，不缩减U7每张照片对全部必要节点的复核，避免漏掉前置被拆等反证。旧空间宿主的局部verify／全局assess设计没有在本轮统一改写。

## 接口

- `resolve_goal(task, sources, query, *, use_aliases=True, normalize_language=True)`：保守选择，歧义仍抛错；两个开关用于消融。
- `goal_candidates(...)`：返回带 `task_sha256/query/title/level/selected_node_ids/source_ids/interpretation` 的可追溯候选，不能产生完成事实。
- `remaining_plan(session)`：只读快照，包含 `current_action/remaining_steps`；每个未来分支 `conditional=true`。不声称最优POMDP、观测概率已校准或保证完成。
- `POST /api/guidance/u7-demo/sessions`：可选 `guidance_policy`，默认 `evidence_guided`；可指定 `scene_guided` 对照。会话内不切换策略。
- U7回复含 `remaining_plan`，空间宿主的 `execution.remaining_plan` 同样提供结构计划；宿主为步骤补充现有 `action_id/presentation_id` 资产映射。当前前端继续使用原execution和简短demo_flow，无需重新编译Unity。
- 目标不明确时，U7错误提示列出候选；原goal-preview另返回结构化 `candidates`。没有放宽接受任意客户端节点ID的规则。

## 本轮实验与统计

最终报告：`Manual2AR-Data/runs/dev/online-planning-20261116/experiment-v8/REPORT.md`。JSON、CSV、代码快照、清单SHA与待标注清单同目录。

数据有三种角色，分开报告：

- **真实缓存诊断：** 非演示HTTP请求48份，其中40份成功、8份失败；31个不同照片字节SHA，不是31个独立现场。模型成功记录输出124个条件，46个未知（37.1%），不是错误率。
- **已接受事件重放：** 14个历史会话的40快照，包括26个已接受照片快照和14个人工确认快照。仅2快照来自正式GT，其余38来自原自动候选r02，按定义分组，不把候选当成新的正式GT。
- **软件控制与开发预期：** 27条研究者编写的目标预期，含历史问法、已有控制问法及来源派生变体，不是留出集。758个控制状态是729个视觉三值/目标组合与29个合法正向人工确认前缀，未穷举人工否认和时序回退。

旧源码与新源码分别冻结。目标采用别名×语言规范化的2×2消融，另保留旧源码对照；共同的主体约束修正单独说明。规划采用证据策略×条件表示的2×2消融。真实缓存的动作分布没有变化，未包含上述4种风险情形，不能宣称实拍装配成功率提高。

历史调用有88份元数据（整图/修复59，局部ROI29），报告token合计350588，elapsed_ms求和652043；不是本轮费用、墙钟耗时或完整账单。本轮新增VLM/GPU调用均为0，缓存重放与符号规划在CPU完成。Colab CLI只读查询未发现活动会话，无需为这轮统计分配GPU。

独立逐条件图像标签仍缺失，所以视觉准确率、真实进度准确率、装配成功率、AR精度及交互最优性保持未评价。待标注清单涵盖成功和失败请求的照片，不显示模型预测，也不替用户填写标签。既有编译人审是1份批准、6份待审，不能当照片真值。

## 本机复现

先读最终报告及 `plan.json`。冻结清单记录原始缓存路径及SHA，运行器检查计划本身、数据和代码在运行前后未变；不覆写原记录或已有结果。

```bash
# 从同一before快照和未修改的数据准备一个新实验目录
.venv/bin/python -B -m tools.evaluation.online_planning prepare \
  --data ../Manual2AR-Data \
  --output ../Manual2AR-Data/runs/dev/online-planning-repeat \
  --baseline-goals ../Manual2AR-Data/runs/dev/online-planning-20261116/inputs/before/goals.py

.venv/bin/python -B -m tools.evaluation.online_planning run \
  --output ../Manual2AR-Data/runs/dev/online-planning-repeat
```

`before/goals.py` 与同目录 `state.py` 是本轮修改前保存的源码。代码或路径改变后应建新实验计划，不通过删除结果重用旧目录。仅克隆Git不包含缓存与上述快照，移机需要另外提供Data；本轮没有推送远程。

开发目录v1保留运行器Sources类型错误，v2—v7保留方法调试、口径修正及契约审查过程；这些不是独立模型重复试次。最终方法使用过这份开发集，没有新的盲测结论。仍未匹配的两条口语问法保留在CSV，不因失败而移出分母。
