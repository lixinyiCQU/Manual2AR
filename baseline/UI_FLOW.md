# U7 评估、操作核验与人工确认（0.7.1）

> 当前模块二保留开箱、首次打印等教材任务，并提供 [U7 汇报 Demo](U7_DEMO.md)。本文保留对应研究接口与原流程说明，审核、编译等开发入口不在演示菜单中显示。

本阶段按用户视频及最近实际会话修复前端流程。视觉模型、已冻结任务、检查条件与原评价结果不变；验收聚焦软件架构鲁棒性，不追加真实模型试跑。

## 用户流程

| 阶段 | 主界面按钮 | 行为 |
| --- | --- | --- |
| 相机已启动，尚未评估 | 评估现场 | 用户点击后提交目标及必要前置操作的照片评估；相机启动和实时帧不自动调用模型 |
| 初始照片证据不足 | 重新评估现场 | 调整取景后主动重试；未知不授权完成 |
| 当前操作可指导或正在操作 | 拍照核验 | 检查当前操作结果，不重复检查已通过前置操作 |
| 当前操作等待人工确认 | 查看结果与人工确认 | 重开已接受的结果，不重新调用视觉模型 |
| 本次目标完成 | 查看完成结果 | 查看结果或返回任务列表 |

每阶段只显示一个主动作。AR 部件识别放在 AR 指导的准备窗口内，避免与“评估现场”混为同一个按钮。

照片返回后先显示结果窗口。默认显示所有相关步骤的可见检查进度、当前阻碍和下一步动作；不因前一步证据不足而隐藏后一步已看到的结果。详细检查项及模型原话放在“查看识别详情”，模型误认也原样保留。现场摘要与人工项目分栏；当前操作的所有人工条件列在同一窗口，用默认未勾选的确认框一次确认。关闭窗口不写入进度。对观察结果有异议时，可在窗口内明确重新拍摄，不能由重拍替代人工确认。

人工确认按官方最细操作分组。底座的紧固和方向一起确认；后续支架操作的方向在该操作视觉条件满足后确认，不提前确认尚未执行的操作。

## 状态与证据边界

- `execution.visual_conditions` 返回当前操作的可见条件、程序结果、已接受的模型观察说明及是否沿用先前证据。说明必须与当前事实的 evidence_id 对应；上下文失效或新会话不沿用旧观察文字。
- `execution.manual_conditions` 列出当前操作全部待人工确认项。批量确认与视觉、依赖、任务及会话版本绑定，作为一个人工事件提交；仍兼容旧客户端当前单项确认，不允许混入后续操作或视觉条件。
- 初次评估、当前操作核验及人工确认各自独立。失败、过期、跨会话结果不推进状态；无证据不自动判完成。
- 切换相机或画幅建立新会话，清除旧分割跟踪、冻结显示、旧帧和临时弹窗；旧会话证据文件保留。需要用户重新主动评估。

## 卡住问题

实际 Windows 日志有 `SpatialCallout.Show → RenderFrame/RefreshCallout` 空引用。旧标注代码假设所有视觉对象都具有旧 asset、label 和 anchor；部分跟踪／新资产结果不满足该假设。共享标注入口现会隐藏缺少必要字段的标注，并避免用新 presentation 访问空的旧 asset。

相机重建还曾保留 `partsDisplayActive`：后台继续接收新帧，前端却等待已结束的旧跟踪来显示画面。重建统一调用跟踪取消与显示清理，用 epoch/session 拒绝旧回调；重建结束或失败均解除 changing 状态。物理驱动层切换仍需用户实际确认，本轮用受控帧源验证恢复路径。

## 2026-11-12：反馈与重试

操作后的照片核验未通过时，留在同一步；结果窗口关闭后可调整取景并再次点击“拍照核验”，不再次引导进入同一步AR。只有初次评估需要操作，或已完成前一步而确实进入下一步时，才提供AR入口。相同步骤与模式的新核验版本不会重置AR准备状态；切换操作、改变模式和新会话仍执行原清理。

默认反馈规则：

- 使用中性、直接的短句；先说结果，再说用户下一步动作。
- “未确认”表示照片不足，不能改写为“未安装”；“可见检查通过”不能改写为机械紧固已确认。
- 默认不展示契约、事实、证据框、实验观察等实现术语，不重复官方长文和免责段落。
- 保留必要的官方操作及人工检查要求；没有可靠识别时不伪造简短确定结论。
- 模型原话可在详情中查看；完整诊断仍在后台记录，用户可重拍质疑结果。

界面固定用语示例：“正在核验，请稍候…”；“本步尚未通过。请检查安装位置，调整后重新拍照。”；“本步仍有部位未确认。请拍清未确认的部位后重拍。”；“当前步骤的照片检查通过。请核实下方人工项目。”；“照片检查和人工确认均已通过，任务完成。”
