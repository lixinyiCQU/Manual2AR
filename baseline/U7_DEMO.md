# U7 汇报演示：提问及拍摄现场生成AR指导

这是用于展示目标定位、现场进度、人工确认和 AR 指导闭环的精选演示。任务读取已审核的 U7 GT，动画复用现有 U7 资产；本次不在现场重新编译官方资料。

2026-11-16后端优化：支持已审核别名与有限问句规范化，不明确时列出来源候选；部分正证据但仍缺视觉细节时先核实，默认采用evidence_guided。结构计划和缓存对照见 [方法与试验](ONLINE_PLANNING.md)，预设演示仍不计入研究结果。

前端同步调整见 [界面复评](../docs/U7_FRONTEND_UPDATE_20261116.md)：歧义目标先选择官方任务；补拍提示对应具体部位和未知原因；界面阶段不再使用易混淆的三步编号。

## 三分钟演示路线

1. 关闭旧客户端，运行交付目录中的“启动教学系统.cmd”，进入模块二“操作指导”。列表保留“打印机开箱”“首次打印”等原任务，选择“提问及拍摄现场生成AR指导”进入U7演示。
2. 保持默认“历史照片演示（预设）”，选“底座已装，支架待滑入”。输入“安装料盘支架”，或选择示例“安装料盘底座及滑入料盘支架”。点击“评估现场并生成计划”。
3. 先看侧栏的现场结果、官方两步进度及下一步，再点击“核实人工项目”。同一窗口列出底座方向与紧固两项要求；勾选后点击“确认并继续”。没有勾选不会通过，关闭窗口不推进进度。
4. 底座确认后直接展示支架滑入动画。点击照片可调整示意位置；“重播本步”可重新播放，动画不改变核验进度。核验未通过时保留当前步骤，调整后继续拍照核验，不强制重播。
5. 在照片下拉框选“支架已装，底座固定处被遮挡”。旧动画会先清除。点击“核验当前照片”，显示支架检查结果；底座沿用本次演示中已核实的记录。
6. 点击“核实人工项目”，确认支架方向，展示“本次目标已完成”。可点击“官方步骤”解释计划来源；未拍照或未生成计划时也可先浏览完整U7步骤。

历史照片中底座一直在位，所以默认路线从核实底座开始。没有把这张照片说成“尚未安装底座”，也没有伪造从零安装底座的画面。

## 其他可展示场景

| 输入或图片 | 应有结果 |
| --- | --- |
| 安装料盘支架 | 目标为底座与支架两个操作 |
| 安装支架底座／安装料盘底座 | 只完成底座后结束，不再要求滑入支架 |
| 滑入料盘支架 | 目标为滑入，但先核实必要的底座条件 |
| 滑入料盘底座 | 按官方唯一滑入操作解释，并展示官方步骤；没有新增“滑入底座”动作 |
| 安装料盘底座及滑入料盘支架 | 两个子目标合并，按官方依赖顺序执行 |
| 新会话直接选择已装支架照片 | 显示支架可见、底座固定处被遮挡；不继承其他会话确认，不直接宣布完成 |
| 下一步怎么做 | 先选择整个料盘支架安装、仅安装底座或滑入支架；选择本身不评估照片、不推进进度 |
| 支架步骤再次核验底座照片 | 保留底座完成记录，提示支架尚未通过，调整后再核验 |
| 开箱或其他未支持任务 | 明确无法对应本演示任务，不扩展成没有资料和资产的流程 |

## 两种模式

**历史照片演示（默认）**使用两张已测试照片与明确编写的场景观察。所有记录均标记为演示，不计入编译率、识别率、人工审核通过率或正式规划评价。预设观察不是原模型回复，也不是独立人工图像标注。切换场景会重新检查相关可见状态，反向切换不会沿用已被反例推翻的进度。

**实时拍摄（真实模型）**需要选择摄像头，手动启动并拍摄。启动相机不会调用模型；取景期间不能提交旧照片，拍摄后冻结画面，点击评估或核验才调用模型。每次操作核验需重新拍摄，避免使用操作前的照片。每张照片检查本次目标及必要前置的视觉条件，明确反证会撤销已失效的前置进度；普通遮挡只能保留同会话已经核实的条件。模型可能失败、误认或无法确认；请求失败不更新进度，人工确认不能替代未通过的视觉条件。两种证据不能在同一会话中混用。

需要补拍时，侧栏会分别列出如“两颗固定螺丝：被遮挡，请换角度拍清”的提示；部分检查通过时，也显示照片已支持的内容。已接受的照片需补拍后再评估，尚未接受的失败请求可用原照片重试。只在可重播当前动画时显示“重播本步”；完成或人工核实阶段不显示。

照片或资料载入失败时，主按钮提供重新载入；请求处理中也可返回任务列表。闲置30分钟的会话会在新建会话时回收，正在核验的会话不会被回收。

两种模式使用同一 GT 状态与依赖调度逻辑，以及同一资产库。默认 AR 是**照片上的动画示意**，可手动调整位置，不声称完成实机空间标定或自动部件定位，不改写原相机、标记或锚点配置。开箱和首次打印沿用原教程与配置，实机空间指导仍可从原教材进入；候选审核、自动编译等研究入口继续隐藏。

## 资料、记录与边界

- 任务来自 `baseline/ground_truth/u7/v1/state-validation/`，两个操作节点、螺丝联合检查；GT 及原绑定不改写。
- 匹配沿用官方层级、部件与动作规则，新增明确组合目标；不声称实现通用语义检索模型。
- API：`/api/guidance/u7-demo`。`POST /goal-preview` 只读查询目标与来源候选，不建会话或调用视觉；选择候选后再由用户点击评估。检查任务、会话、版本、照片哈希和人工条件列表；关闭会话拒绝迟到结果。
- 素材位于模块二运行目录 `u7-demo/assets-v1/`，包含原照片哈希、历史路径及预设说明。用 `python -B -m tools.build.prepare_u7_demo` 从指定历史记录准备；缺少原记录会报错，不自动换图。
- 演示记录位于模块二运行目录 `u7-demo/runs/`，独立于原18次编译、用户审核和实际装配记录。演示者点击确认不构成正式人工审核标签。

本轮用受控服务验证界面和流程，不额外调用真实模型；真实摄像头与物理 AR 精度仍需现场验证。

## 本轮采用的开发思路

参考 [CheckManual](https://arxiv.org/abs/2506.09343) 将资料依据、现场对象和操作分别对齐；参考 [SayCan](https://say-can.github.io/) 分开处理目标相关性与前置条件；参考 [Inner Monologue](https://proceedings.mlr.press/v205/huang23c.html) 根据核验反馈更新后续指导；参考 [KnowNo](https://proceedings.mlr.press/v229/ren23a.html) 将必要核实作为正式交互。本演示没有复现其学习算法或统计保证，仍使用已审核GT、现有三值状态引擎和规则式目标匹配。

当前真实视觉链路是整图观察、框选区域裁剪放大、局部复核；不包含像素级分割。照片示意AR不依赖分割或三维定位，也不冒充实体配准结果。
