# U7 引导式安装与完成状态

本次仅扩展 U7 的自动空间指导；保留原有官方章节、参考图片、相机标定、作用点、工作坐标和组件动作管理。

## 使用步骤

1. 从步骤总览右侧进入 U7 的空间指导，启动相机。让固定定位标记及安装位置入镜。
2. 有缓存作用点时，画面在缓存位置显示「开始本步」。确认打印机与标记没有发生相对移动后点击；没有缓存时先进入「空间锚点配置」。
3. 阅读弹出的本步说明及官方图片，点击「开始指导」。图文收起到右侧入口，自动调用 VLM，先显示识别框，随后显示 GPU 掩码／跟踪；当前步骤目标的分割及同帧跟踪掩码就绪后才显示三维教学动画和方向坐标。
4. 底座步骤仅高亮灰色底座。按指导操作后，点击「检查安装」。系统重新取当前帧进行专用可见安装核验；通过后弹窗提示，用户确认完成后才进入滑入支架步骤，未通过则保留本步并给出建议。
5. 支架步骤先展示图文；摆好底座和支架后手动点击“识别部件”，分别高亮两部件并播放下滑动画。再次检查最终可见安装；通过后 U7 在总览及顶部章节导航显示绿色勾选。

顶部设备／调试标题及「我已操作」已移除。返回图文和空间锚点配置并排放在底部右侧。右侧优先显示运行状态、部件位置和安装建议，官方图文可随时重新打开、放大。

GPU 不可用时尝试本机 CPU 分割与跟踪；只有获得当前目标的有效同帧掩码才显示空间动画。分割仍不可用时保留定位照片和识别框，不把旧掩码绘制到新帧，也不自动制造三维锚点。定位、分割、动画均不能替代安装核验。螺丝扭矩仍需要用户按官方说明确认。

## 完成状态

- API `chapter_completion` 返回各章 `state_id / completed / source`。
- 图文章节由独立的「已完成本章」按钮记录用户确认，拍照参考仍由拍照窗口中的按钮执行。
- 空间章节拒绝用手动标记替代视觉核验。U7 必须底座和支架两步均通过。浏览、模拟回放和分割成功不会显示完成勾选。
- 当前章节在总览行和顶部可点击章节按钮中高亮。总览移除「已浏览」及学习记录入口；底层诊断日志仍然保留。

## 流程与契约

`SpatialStepFlow` 独立管理准备、用户开始、图文介绍、自动定位及复检，不承担相机、GPU 或动画采样工作。每一步沿用 epoch、帧号、SHA 和 job ID 防止旧请求覆盖新步骤。

`Reply.preflight` 返回缓存目标／工作坐标是否存在、标记是否可见，以及缓存终点在当前画面中的投影。该投影是预览，不授权动画。用户点击后，通过 `POST /sessions/{id}/reuse` 明确确认场景未移动；后端要求新鲜、标记可见且标定有效的当前帧才沿用缓存。

进入后，`/locate` 按动作传入 U7 专用 Prompt。底座步骤只提交底座给分割器；支架步骤提交两个目标。`PartStatus.guidance` 保存 VLM 简短操作建议，`next_action` 表示当前分割／跟踪状态。主动复检停止旧跟踪、等待新的相机帧，再调用 `/verify`。只有底座专用验收通过且用户确认后才进入支架步骤。

## 三维文字

`GuidanceVisual.text_labels` 的每项包含 `id / text / brief / source / reference_space_id / position_m`。位置使用已标定标记坐标系，单位为米，最多四个标签，文字作为纯文本显示。

- `SpatialTextRenderer`：Windows RGB 适配器，用显示帧对应的位姿和内参投影三维锚点，生成面向用户的标签，并按深度调整大小。文字仅保留短名称；与同帧部件标签共同避让，安装核验反馈集中显示在弹窗及画面状态条。
- `VisualWorldTextRenderer`：世界空间 Canvas 文字适配器，要求调用方提供已注册的 `UnityWorldFromReference` 和观看相机，按同一米制锚点放置面向相机的文字。不提供有效世界参照时隐藏。

二维分割框不能直接填入三维 `position_m`。原生 AR 世界注册、真实深度与遮挡关系不在本次 Windows 演示范围。

## 验证

Python 测试覆盖文本／空间完成来源、准备状态与显式缓存确认、底座专用目标、U7 前置顺序和旧请求隔离。Unity 端到端测试使用合成 RGB、受控 VLM 和本地假 GPU，覆盖准备按钮、首次自动定位、底座核验后的显式用户确认、最终完成勾选及三维文字适配器；不调用实体相机或外部模型。现场精度与真实 GPU 性能需实机复测。


## 弹窗与阅读卡片更新

统一的 `AppModalBackdrop` 在打开弹窗时生成一次当前应用画面的模糊快照，并叠加暗色遮罩；关闭、隐藏或销毁弹窗时同步移除遮罩。嵌套弹窗各自管理层级，关闭内层后保留外层状态。快照只存在内存，不写入日志或上传。

总览的「查看官方指南」位于返回按钮上方，通过 `/api/learning/wiki/resolve` 从本地快照查找文章，再复用模块一的 `PrinterLearningWikiView` 展示，不打开外部浏览器。此接口仅按已安装归档索引解析 URL，不请求外部网址。

章节名称固定在教学卡片顶端，分步骤选择器显示当前序号及总数；正文不重复标题和计数。「操作指导」使用独立的蓝色卡片；适用版本等原文合并到「补充说明」，来源摘要与引用不变。

### GPU 不可用时的本机运行

U7 识别部件仍由 VLM 给出部件语义、框和前景点。分割前以短超时检查 GPU；连接文件缺失、服务未启动、初始化失败时，自动改用本机 CPU 的 OpenCV GrabCut 分割及模块一的双向 LK 光流跟踪。界面会显示“本机 CPU”，后台记录 `parts.provider_fallback`，不需要用户切换。

跟踪期间 GPU 断开时，使用上一张已匹配画面及其掩码初始化 CPU，再跟踪到当前画面，避免用旧识别框冒充当前位置。GPU 失败后 60 秒内的新识别直接走 CPU；冷却结束后下一次拍照重新尝试 GPU。当前 CPU 会话保持在 CPU，不在过程中来回切换。

CPU 模式适合本地调试；快速移动、遮挡、缺乏纹理时效果可能弱于 Cutie。质量不足时隐藏掩码并提示重新识别，不生成假矩形高亮，也不替代最终安装状态的 VLM 核验。


## 测试视频后的交互调整

- 顶部并列「摄像头管理」及「动作管理」。画幅、启动、切换镜头集中在摄像头弹窗。主教学画面移除步骤与螺丝下拉菜单；当前子步骤固定在相机框内。
- 底座步骤同时显示两颗螺丝的模型与名称。`Reply.companion_visuals` 仅携带另一个已保存、已授权、未失效且在视野中的真实作用点；缺少第二点时需在「空间锚点配置」中配置，不用相对偏移猜测。
- 拧紧示意为默认单次 90° 的摆动（可在动作管理中调整），再渐隐、复位、重新出现。它表示动作方向，不代表所需圈数或扭矩；静态显示及速度控制保留。
- 「识别部件」只触发定位、分割和跟踪；「检查安装」只核验当前可见安装。底座通过后需用户确认进入子步骤 2；全部完成后可留在空间指导或返回图文。
- 部件名称与作用点名称使用同一相机局部矩形占位表避让，预留顶部步骤及底部反馈区域。小画面没有足够空间时以最小重叠位置显示，仍需实机验证可读性。

### 画面反馈使用契约

复用公共 `AppTheme` 字体、圆角和 `AppIcon`，通过 `SpatialFeedbackView` 呈现：蓝色表示准备／处理状态，绿色表示核验通过，红色边框及弹窗表示本次核验需调整。红框是整个检查画面的提示，不冒充异常物体的定位框。安装结果来自 `/verify`，识别成功不作为验收通过。弹窗显示期间状态条保持本次反馈，关闭后恢复当前链路状态。

`PartStatus.phase=located` 仅允许显示 VLM 框与二维标签；`tracking`、掩码及当前目标均有效后才开放模型、轴及动作。跟踪停止或目标丢失时立即隐藏空间动画；所有掩码与几何仍要求帧号、SHA、会话和 job 一致。

### 空间画面文字与动作管理

子步骤与取景提示使用小字号、带阴影的无底框文字，跟随当前帧中定位标记的投影；未检测到标记时改为画面内的简短文字，不保留旧位置，也不占据整条画面。

动作管理在动画实例尚未就绪时不建立编辑弹窗；独立面板即便收到空数据也提供明确提示与关闭入口。面板支持关闭按钮及 Escape，缺少旧版组件 XYZ 数组时采用零偏移默认值。

### U7 统一画面显示

画面左上角固定图例，用现有三维资产的缩略图及高亮色块说明含义；名称不跟随现场目标。目标附近只保留一句祈使式操作指导，不显示章节名、规格状态、核验结果或步骤计数。详情见 `GUIDANCE_DISPLAY_CONTRACT.md`。

操作文字使用已标定的米制作用点投影到当前画面，标记丢失时隐藏；文字采用白字黑描边并避让图例。核验反馈留在右侧面板，动画和分割高亮仍可同时显示。原生 AR 可使用同一契约的注册空间坐标显示文字。

底座步骤保留用户开始后的自动识别。进入“从上向下滑入料盘支架”后，关闭图文只提示两者同时入镜，摄像头继续取景；必须点击“识别部件”才发出 VLM／分割请求，切换步骤或关闭说明不会自动拍照。
