# 不同颗粒度目标与现场指导（0.7.0）

> 当前模块二保留开箱、首次打印等教材任务，并提供 [U7 汇报 Demo](U7_DEMO.md)。本文保留对应研究接口与原流程说明，审核、编译等开发入口不在演示菜单中显示。

本阶段保留官方完整任务和原始候选，另为每次现场会话选择目标范围。目标选择不修改任务字节、不替换核验条件，也不会产生完成事实。

## U7 使用方式

在新版 Unity 的“操作指导 → 候选人工审核与 U7 实测”中，选择原第2次或第3次 U7 候选，点击“U7现场试验”。进入相机前输入问题，点击“对应官方步骤”，阅读目标、解释和必要前置操作，再点击“使用此目标”。也可以从“从官方资料生成 AR 任务”进入，原问题会带入目标选择。

| 问题 | 本次目标 | 必要操作范围 |
| --- | --- | --- |
| 安装料盘支架 | 完整 U7 | 安装底座 → 滑入支架 |
| 安装支架底座 | 安装底座 | 安装底座；通过后结束 |
| 滑入料盘底座 | 按官方动作解释为将支架滑入底座 | 先核实底座，再滑入支架 |

第三种表达会明确显示解释，不能把底座当成要滑入的活动部件。“滑入螺丝”等无法对应官方操作的问题不放行。需要改变目标时，点击“任务目标”；明确选用新目标后重新建立会话，旧证据记录保留，新会话重新评估现场。

启动镜头后，首次现场评估覆盖本次目标及其必要前置操作。右侧持续显示官方操作流程、现场进度、剩余操作及当前步骤，核验反馈单独显示。

- 底座可见条件通过、紧固和方向待确认：显示视觉支持及全部待人工条件，逐项实际确认。
- 底座视觉与人工条件都通过：完整安装或滑入目标进入支架 AR 指导；支架结果未知不会被当作已完成，也不再阻止提供下一步指导。
- 仅安装底座：底座通过后完成本次目标，不要求继续安装支架。
- 支架可能已经装好：先依据照片核验；不能只因用户说已完成而跳过。
- 底座身份或可见细节不足：明确提示补拍，人工紧固确认不能覆盖视觉失败。

现场策略还会对整图定位出的区域进行局部身份复核，覆盖“未安装”判断。没有可复核区域时保留未知；局部确认目标确实未安装时可以提供安装指导，不要求不存在的螺丝先被识别。裁剪仍来自同一照片，不算独立新视角。

进入 AR 指导仍需有效相机标定、标记及作用点。下一步入口说明这些准备要求；不会自动确认旧位置仍有效。动画播放不改变安装进度。

## 调度与证据

`任务目标 → 官方操作及依赖 → 现场观察 → 规定的人工确认 → 可执行操作 → AR 指导 → 操作结果核验`

官方最细操作是 AR 指导单位；螺丝联合检查、方向、实际紧固是操作的完成条件，不被拆成额外安装步骤。当前任务层级来自引用原文的操作、显式依赖及可识别的官方编号章节。无明确编号章节时，父标题标记为编译摘要，不声称恢复了整个开箱层级。

核心 `Session` 新增 `target_node_ids` 和 `guidance_policy`。默认 `strict` 保留原受控评价语义；现场宿主启用 `scene_guided`。叶目标保留必要依赖，任务 SHA 不变。允许开始指导与接受完成证据分别判断：已核实依赖后可以指导结果未知的后续操作，正向人工确认仍须满足全部规定视觉条件。

会话创建后目标范围固定。任务、来源、照片 SHA、session/action/frame、epoch/revision 以及旧人工确认拒绝规则继续生效。生成候选和语义审核仍不等于人审批准或实际安装验收。

## API 与实现入口

- `POST <spatial-prefix>/goal-preview`，输入 `intent`，返回 `matched` 或 `clarification_required`、解释、官方操作路径和任务 SHA。
- `POST <spatial-prefix>/sessions`，可带 `goal_intent`；服务端重新解析，创建固定范围的新会话。
- `POST .../assess`：明确重新评估本次目标及全部必要依赖，包括已完成操作；新反证会使相关证据失效。
- `POST .../verify`：首次覆盖目标范围，之后聚焦当前操作；核验支架时不再重复底座螺丝 ROI。未查询的旧证据不是本次新观察。
- `POST .../manual-conditions`：接受当前规定人工条件；不得替代视觉条件。

`execution` 新增 `goal_title/current_step/task_summary/steps/target_node_ids/needed_node_ids/guidance_ready`。模型失败不更新进度，错误提示保留的当前步骤。初次观察中的未来操作未知不会被展示为当前必须补拍的阻塞项。

明确重新评估后，原已通过操作若因当前视觉证据不足或反证需要重新核实，反馈会指出哪些操作受影响；原人工确认事件保留，但不把失效的完成状态继续当作操作前提。

代码入口为 `goals.py`、`state.py`、`ar.py`、`photos.py`、`vision.py`、宿主 `guidance/baseline_spatial.py` 及 Unity `SpatialGoalFlow.cs`。编译器仍从完整父章节编译；窄用户目标由运行时选择。照片提示携带用户问题、相关官方操作和原文，但用户声明不作为现场事实。

## 验证与限制

新增受控回归覆盖父/叶目标、依赖闭包、底座单独结束、底座人工通过后指导未知支架、后续观察范围、明确重新评估的反证、迟到或错误结果以及目标恢复。两份原始 U7 候选各自完成三种问法的受控宿主闭环；不是实际摄像头或真实人工验收。

本阶段证据位于 `/home/lixin/projects/Manual2AR-Data/runs/baseline/granularity-20261111-v1/`。真实模型历史照片试跑、受控软件事实、Unity 界面验证分别记录。原18次评价、389个冻结文件及原人审标签不被重封或重算；新方法不能混入旧成功率。

用户已明确本轮以软件架构鲁棒为验收重点：有效结果按规则处理，未知不授权完成，契约失败不写入进度，过期或跨会话证据拒绝，明确重新评估能解释依赖状态变化。真实模型试跑保留为开发诊断，不以偶然识别成功作为软件验收标准。

目标匹配当前采用来源支持的词面、部件与动作结构规则；不声称任意语言通用理解。整套“开箱”及其他未覆盖任务需完整官方任务和 AR 能力，不能用 U7 冒充。视觉语义仍可能误认或违反输出契约；历史照片试跑没有独立真值标签，不能充当现场准确率或物理 AR 精度。
